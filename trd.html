Technical requirements document

SleepSync · Draft 1.0 · November 6, 2026

1. Application title and full description

Application title: SleepSync — Rest & Restore

Full description: SleepSync is a sleep-wellness companion designed to help users build a calming bedtime routine. Its Cycle area presents a sleep-session timer and sleep-related information; Relax offers relaxation-audio choices; Guides provides educational sleep-hygiene tips and information about sleep stages; and Trends lets users record sleep duration and review a score or summary. SleepSync is intended for general wellness and education, not diagnosis or treatment. The supplied materials mention heart-rate stability, but heart-rate sensing and automatic sleep-stage detection have not been verified and should not be represented as measured features without confirming the Android app implementation.

2. System boundary

SleepSync currently has two distinct deliverables: an Android app represented by user-provided screenshots and a downloadable APK, and a static companion website implemented with HTML, CSS, and JavaScript. Website behavior must not be used as evidence for Android-app architecture.

3. Android application: known and unknown

Known from project materials: an APK download link was provided; an AIA project file is reported to exist; the screenshots show Cycle, Relax, Guides, and Trends interfaces.

Platform: the AIA extension is associated with MIT App Inventor projects, but the project file has not been reviewed. Confirm the authoring environment and app build/version directly from the AIA and APK before finalizing this document.

Unconfirmed: app architecture, component and extension inventory, Android API/version targets, persistence mechanism, audio implementation, permissions, network behavior, sensor integrations, build process, and release signing setup.

4. Website implementation: verified

  • Delivery: static files: index.html, privacy.html, styles.css, app.js, and local image assets.
  • Sleep entries: browser local storage under sleepsync.entries.v1. Entries are device/browser-specific and are not synchronized to the Android app.
  • Timer: a timestamp is stored locally under sleepsync.session-start.v1 so a web session can resume after reload.
  • Score: a simple website estimate based on entered sleep duration; it is not a medical measurement.
  • Relaxation audio: generated client-side using the Web Audio API after user interaction; the website does not record microphone audio.
  • Navigation: Cycle, Relax, Guides, and Trends are client-side sections in the homepage.
  • External link: the header Download button points to the developer-provided Google Drive file URL. The Drive file's availability and download confirmation are controlled by Google Drive.

5. Data and privacy requirements

  • Explain the collection, purpose, storage, sharing, retention, and deletion of data separately for the website and Android app.
  • Do not claim that the Android application is offline-only, uses local-only storage, or collects no data until its code, manifest, and behavior have been checked.
  • Do not collect health-sensor data without a confirmed feature, clear user permission, and an accurate privacy notice.
  • Provide a clear way to delete locally stored website entries.
  • Keep release signing keys, passwords, and other signing credentials private.

6. Health and measurement constraints

No verified heart-rate sensor or automatic sleep-stage measurement is documented here. Values shown as sleep stages or scores must be described as estimates or educational content unless the Android implementation and measurement method are confirmed and validated.

7. Verification checklist

  • Inspect the AIA source and record its actual components, storage, blocks, and permissions.
  • Inspect the APK manifest and verify the app package, version, minimum/target Android versions, and requested permissions.
  • Test Cycle, Relax, Guides, and Trends on a physical Android device and document expected behavior.
  • Verify if audio works offline, whether data persists across app restarts, and how users can clear saved data.
  • Confirm whether sensor access, network requests, analytics, ads, or third-party SDKs exist before making privacy statements.
  • Test the published website and Drive link from a signed-out browser before sharing them publicly.
